# وثيقة التصميم التقني - نظام الألوان البيج

## نظرة عامة

يهدف هذا التصميم إلى تحويل نظام الألوان الحالي للموقع من النظام الداكن البنفسجي إلى نظام ألوان جديد يعتمد على اللون البيج كلون أساسي. سيتم تنفيذ هذا التحويل من خلال تحديث متغيرات CSS الجذرية وضمان التوافق البصري والوضوح في جميع عناصر الواجهة.

### الأهداف الرئيسية

- تطبيق نظام ألوان بيج متناسق عبر جميع صفحات الموقع
- الحفاظ على مستوى التباين المطلوب لإمكانية الوصول
- ضمان وضوح العناصر التفاعلية والنصوص
- الحفاظ على الهوية البصرية للموقع مع تحسين تجربة المستخدم

## البنية المعمارية

### نظام إدارة الألوان

يعتمد الموقع الحالي على نظام متغيرات CSS المركزية المعرفة في `:root` داخل ملف `css/style.css`. هذا النهج يسمح بتحديث الألوان بشكل مركزي ومتسق.

```css
:root {
  /* متغيرات الألوان الحالية */
  --primary: #6c63ff;
  --bg-dark: #0f0e17;
  --text-primary: #f0eff4;
  /* ... المزيد من المتغيرات */
}
```

### استراتيجية التحويل

1. **التحديث المركزي**: تحديث جميع متغيرات الألوان في `:root`
2. **التدرج التدريجي**: تطبيق الألوان الجديدة بشكل تدريجي للتأكد من التوافق
3. **الاختبار المتقاطع**: فحص جميع الصفحات والمكونات للتأكد من التطبيق الصحيح

## المكونات والواجهات

### 1. نظام الألوان الأساسي (Color System)

#### الألوان الأساسية الجديدة

```css

  /* ألوان الحالة */

  /* ألوان الخلفية */

  --bg-secondary: #F5F5DC;      /* خلفية ثانوية بيج */
  --bg-card: rgba(210,180,140,0.1);  /* خلفية البطاقات */

```

### 2. مكونات واجهة المستخدم (UI Components)

#### الأزرار (Buttons)

```css
.btn-primary {
  background: var(--gradient);
  color: var(--text-primary);
  box-shadow: 0 4px 20px rgba(210,180,140,0.4);
}

.btn-outline {
  background: transparent;
  color: var(--primary-dark);
  border: 1.5px solid var(--primary);
}
```

#### البطاقات (Cards)

```css
.card {
  background: var(--bg-card);
  background-image: var(--gradient-card);
  border: 1px solid var(--border);
  color: var(--text-primary);
}
```

#### الشارات (Badges)

```css
.badge-normal {
  background: rgba(34,139,34,0.2);
  color: #228B22;
  border: 1px solid rgba(34,139,34,0.3);
}

.badge-attention {
  background: rgba(218,165,32,0.2);
  color: #DAA520;
  border: 1px solid rgba(218,165,32,0.3);
}
```

## معالجة الأخطاء

### استراتيجية التعامل مع الأخطاء

1. **التحقق من دعم المتصفح**: التأكد من دعم متغيرات CSS
2. **القيم الاحتياطية**: توفير ألوان احتياطية للمتصفحات القديمة
3. **التحقق من التباين**: فحص نسب التباين تلقائياً
4. **الإبلاغ عن الأخطاء**: تسجيل أي مشاكل في تطبيق الألوان

```css
/* مثال على القيم الاحتياطية */
.btn-primary {
  background: #D2B48C; /* قيمة احتياطية */
  background: var(--gradient); /* القيمة المفضلة */
}
```

### معالجة حالات الخطأ

```javascript
// فحص دعم متغيرات CSS
function checkCSSVariableSupport() {
  if (!window.CSS || !CSS.supports('color', 'var(--primary)')) {
    console.warn('CSS Variables not supported, falling back to static colors');
    return false;
  }
  return true;
}

// فحص نسبة التباين
function checkContrastRatio(foreground, background) {
  const ratio = calculateContrastRatio(foreground, background);
  if (ratio < 4.5) {
    console.warn(`Low contrast ratio: ${ratio}. WCAG AA requires 4.5:1`);
    return false;
  }
  return true;
}
```

## استراتيجية الاختبار

### اختبارات الوحدة (Unit Tests)

1. **اختبار تطبيق الألوان**: التحقق من تطبيق الألوان الصحيحة لكل مكون
2. **اختبار التباين**: فحص نسب التباين لجميع تركيبات الألوان
3. **اختبار الاستجابة**: التأكد من عمل الألوان على جميع أحجام الشاشات

### اختبارات التكامل (Integration Tests)

1. **اختبار المتصفحات المتعددة**: فحص التوافق عبر المتصفحات المختلفة
2. **اختبار إمكانية الوصول**: استخدام أدوات فحص إمكانية الوصول
3. **اختبار الأداء**: قياس تأثير التغييرات على أداء التحميل

### اختبارات المستخدم (User Testing)

1. **اختبار قابلية الاستخدام**: تقييم سهولة استخدام الواجهة الجديدة
2. **اختبار إمكانية الوصول**: اختبار مع مستخدمين ذوي احتياجات خاصة
3. **اختبار التفضيلات**: جمع آراء المستخدمين حول النظام الجديد

### خطة الاختبار التفصيلية

#### المرحلة 1: اختبارات تقنية أساسية
- فحص تطبيق متغيرات CSS في جميع المكونات
- التحقق من نسب التباين باستخدام أدوات آلية
- اختبار التوافق مع المتصفحات الرئيسية (Chrome, Firefox, Safari, Edge)

#### المرحلة 2: اختبارات وظيفية
- فحص جميع الحالات التفاعلية (hover, active, focus)
- اختبار الرسوم البيانية والمؤشرات البصرية
- التحقق من وضوح النصوص والأيقونات

#### المرحلة 3: اختبارات إمكانية الوصول
- فحص باستخدام قارئات الشاشة
- اختبار مع محاكيات عمى الألوان
- التحقق من معايير WCAG 2.1 AA

#### أدوات الاختبار المقترحة
- **Lighthouse**: لفحص إمكانية الوصول والأداء
- **axe-core**: لاختبارات إمكانية الوصول المتقدمة
- **Color Oracle**: لمحاكاة عمى الألوان
- **WebAIM Contrast Checker**: لفحص نسب التباين

### معايير النجاح
- جميع تركيبات الألوان تحقق نسبة تباين 4.5:1 أو أعلى
- عدم وجود أخطاء في أدوات فحص إمكانية الوصول
- التوافق مع 95% من المتصفحات الحديثة
- تقييم إيجابي من 80% من المستخدمين المختبرين

## الخصائص الصحيحة

*الخاصية هي سمة أو سلوك يجب أن يكون صحيحاً عبر جميع التنفيذات الصالحة للنظام - في الأساس، بيان رسمي حول ما يجب أن يفعله النظام. تعمل الخصائص كجسر بين المواصفات المقروءة بواسطة الإنسان وضمانات الصحة القابلة للتحقق آلياً.*

بعد مراجعة معايير القبول، تم تحديد أن معظم المتطلبات تتعلق بالتكوين والتكامل وليس بخصائص قابلة للاختبار الآلي بشكل شامل. ومع ذلك، يمكن تحديد بعض الخصائص المهمة:

### الخاصية 1: تباين الألوان الشامل

*لأي* تركيبة من ألوان النص والخلفية المستخدمة في النظام، يجب أن تحقق نسبة تباين 4.5:1 على الأقل لضمان إمكانية الوصول

**تتحقق من: المتطلبات 2.2، 2.4، 3.5، 4.1، 7.1**

### الخاصية 2: معايير إمكانية الوصول الشاملة

*لأي* عنصر أو مكون في واجهة المستخدم، يجب أن يجتاز جميع اختبارات WCAG 2.1 AA المتعلقة بالألوان والتباين

**تتحقق من: المتطلبات 4.4، 7.2**

### الخاصية 3: وضوح المؤشرات البصرية

*لأي* مؤشر أو شارة (badge) في النظام، يجب أن يكون واضحاً ومقروءاً مع الألوان الجديدة بنسبة تباين كافية

**تتحقق من: المتطلبات 5.3**

## استراتيجية الاختبار المحدثة

بناءً على تحليل معايير القبول، تم تحديد أن هذه الميزة تتطلب بشكل أساسي:

### اختبارات التكوين (Smoke Tests)
- التحقق من تطبيق الألوان الأساسية الصحيحة
- فحص وجود جميع متغيرات CSS المطلوبة
- التأكد من تعريف ألوان الحالات المختلفة

### اختبارات التكامل (Integration Tests)
- فحص التوافق عبر المتصفحات المختلفة
- اختبار الاستجابة على أحجام شاشة مختلفة
- التحقق من التناسق البصري عبر الصفحات
- اختبار مع أدوات إمكانية الوصول

### اختبارات الخصائص (Property Tests)
للخصائص الثلاث المحددة أعلاه:
- اختبار تباين الألوان الشامل (100+ تركيبة)
- فحص معايير إمكانية الوصول (جميع المكونات)
- اختبار وضوح المؤشرات البصرية (جميع الأنواع)

### تكوين اختبارات الخصائص
- الحد الأدنى 100 تكرار لكل اختبار خاصية
- كل اختبار خاصية يجب أن يشير إلى خاصية وثيقة التصميم المقابلة
- تنسيق العلامة: **Feature: beige-color-theme, Property {number}: {property_text}**

### أدوات الاختبار الموصى بها
- **Jest** أو **Vitest**: لاختبارات الوحدة والخصائص
- **Playwright**: لاختبارات التكامل عبر المتصفحات
- **axe-core**: لاختبارات إمكانية الوصول الآلية
- **fast-check**: لتوليد البيانات في اختبارات الخصائص

## خطة التنفيذ

### المرحلة 1: إعداد نظام الألوان الجديد
1. تحديث متغيرات CSS الجذرية في `:root`
2. إنشاء مجموعة ألوان البيج الكاملة
3. تعريف ألوان الحالات والتدرجات الجديدة

### المرحلة 2: تطبيق الألوان على المكونات
1. تحديث مكونات الأزرار والروابط
2. تطبيق الألوان الجديدة على البطاقات والحاويات
3. تحديث ألوان النصوص والأيقونات
4. تعديل ألوان الرسوم البيانية والمؤشرات

### المرحلة 3: اختبار وتحسين
1. تشغيل اختبارات التباين الآلية
2. فحص التوافق عبر المتصفحات
3. اختبار إمكانية الوصول
4. تحسين الألوان بناءً على النتائج

### المرحلة 4: التحقق النهائي
1. مراجعة شاملة لجميع الصفحات
2. اختبار مع المستخدمين
3. توثيق التغييرات النهائية
4. نشر النظام الجديد

## المخاطر والتخفيف

### المخاطر المحتملة
1. **فقدان التباين**: قد تؤثر الألوان الجديدة على وضوح النصوص
2. **عدم التوافق**: قد لا تعمل الألوان بشكل صحيح على متصفحات قديمة
3. **فقدان المعنى**: قد تفقد بعض الألوان معناها البصري التقليدي

### استراتيجيات التخفيف
1. **اختبار التباين المستمر**: فحص آلي لجميع تركيبات الألوان
2. **قيم احتياطية**: توفير ألوان احتياطية للمتصفحات القديمة
3. **الحفاظ على المعاني**: ضمان بقاء الألوان التقليدية (أخضر للنجاح، أحمر للخطر)

## الخلاصة

يهدف هذا التصميم إلى تحويل نظام الألوان بشكل شامل ومدروس، مع التركيز على الحفاظ على إمكانية الوصول وتجربة المستخدم. من خلال استخدام نهج متدرج ومنهجي، يمكن ضمان نجاح التحويل دون التأثير على وظائف الموقع الأساسية.
